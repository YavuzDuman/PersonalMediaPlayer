# Architecture

Personal Media Player is a Windows-only C# app. The solution has the app, the library core, and a small test project.

| Project | Role |
| --- | --- |
| `src/PersonalMediaPlayer.App` | WinUI 3 window, pages, capture, recording, playback, download, and photo tools |
| `tests/PersonalMediaPlayer.Tests` | Tests for download output, stream checks, the browser handoff, playlist listing, captions, saved words, resume positions, HLS rewrite, language names, and home search. It compiles the app sources it covers directly |
| `src/PersonalMediaPlayer.Core` | Library model and file storage. No XAML |
| `extension/` | Unpacked Manifest V3 package for Chrome and Edge. Left out of the solution |

`PersonalMediaPlayer.App` references Core. Core does not reference WinUI.

```
src/PersonalMediaPlayer.App/
├── Views/            Shell, Home, Library, Playlists, Saved words, preview, photo editor, video editor, Download, Merge, Capture, Recordings, Settings
├── ViewModels/       Page state. CommunityToolkit.Mvvm
├── Controls/         Media card, folder row, markup surface, video bar, hover captions, playlist home card, playlist panel, saved-words panel, continue-watching card, crop surface
├── Capture/          Screenshots, OCR, recording, system audio
├── Download/         YouTube lookup, playlist listing, app-lifetime queue, history, subtitle choice
├── Editing/          Photo render, trim, section removal, speed and volume encode, fades, orientation, audio extract, merge, frame grab, timeline thumbnails
├── Playback/         Favorites, bookmarks, resume position, listening volume, playlists, home search, stream check, browser handoff, HLS rewrite, language names
├── Subtitles/        Cue loading, saved words, caption carry through Edit and Merge, the English–Turkish word list, and phrase matching
└── Helpers/          Pickers, clipboard, theme, zoom

extension/
├── manifest.json     Manifest V3. Toolbar action on http and https. Tabs permission only
├── background.js     Sends personalmediaplayer://play/ with the media or page address
├── content.js        Lists direct videos, blob players, and known embed frames
├── picker.html       Choice when a page has several videos
└── picker.js         Picker page script

src/PersonalMediaPlayer.Core/
├── Models/           MediaItem, MediaKind, LibraryFolder
├── Library/          IMediaLibrary, MediaLibrary
└── Storage/          ILibraryStore, FileLibraryStore
```

## UI

`MainWindow` hosts `ShellPage`. The shell is a `NavigationView`. It opens on Home. The other pages are Library, Playlists, Saved words, Recordings, Download, Merge, Capture, and Settings. Home shows continue watching, playlists, recent files, saved words, and downloads that are queued, running, paused, ready, or failed. Each heading has All. Continue watching lists every unfinished video and Back returns to Home. The other buttons open Playlists, Library, Saved words, and Download. A playlist on Home is `PlaylistHomeCard`. The cover uses up to four pictures: one fills it, two sit side by side, three put the first on the left, and four form a grid. A file uses its thumbnail, a YouTube page uses `i.ytimg.com`, and another page uses the `Thumb` stored after it was opened. Play starts the first playable video. The rest of the card opens that playlist. Hovering slides in up to 12 cards and hides them when the pointer leaves. `SavedWordsPanel` stays closed until **Words** or a chosen word opens it. Closing it removes that column. There is no rail. While a playlist is playing, `PlaylistPanel` lists each video with a picture and can reorder the saved list without reopening the current video. Shuffle plays that list in a random order, once each, until every video has played. Repeat plays one video again, plays the playlist again, or stays off. The panel shows which choice is on. Neither choice rewrites the saved order, and both last until the app closes. Undo on the Playlists page or on that panel puts the last removal, move, or sort back, and it does not reopen the video that is playing. Finishing a playlist video marks that entry watched. A right-click marks it watched or unwatched. The mark is stored on the entry for a library file and an online page. **Unwatched only** filters the rows. Closing the panel leaves a card on the video with the name and the watched count, and the video uses the full width. `PlayQueue` is an in-memory list shown beside the player while it has videos, and after **Clear** while **Undo** is still available. **Play next** inserts at the front and **Add to queue** appends. Dragging a row reorders only that list. **Clear** removes every waiting video and leaves the current video playing. **Remove** and **Clear** keep one previous list. **Undo** puts those videos back in the same order. Adding, dragging, or starting the next queued video drops that undo, and closing the message does too. The end of a video, after an A–B section loop is handled, and **Next** take that list before shuffle and repeat. **Previous** does not. After the queue is empty, the open playlist continues from the video that was already current, and otherwise playback stops. Closing the window clears the list and the undo. It is not written to `playlists.json` or a backup. The small player keeps advancing it and shows the list again when the full player returns. `ChapterPanel` lists chapter names and times beside the player when the open video has them. **Chapters** shows or hides that list and does not stop playback. The choice starts with the list open, lasts while the app is open, and is not written to disk or a backup. An online page uses the chapters from the yt-dlp lookup. A file uses the chapters LibVLC reports. Clicking a row seeks to that time, and the row for the current time stays marked. Opening the list again marks that same row. A video with no chapters hides the button and the list. Chapters are not written to disk and do not change bookmarks. The small player hides the list until the full player returns. `ChapterPanel` is the column beside the video, the queue is the next column, and `PlaylistPanel` opens in the column after the queue. Home search matches a library file name and an online video saved in a playlist. Each result shows a thumbnail, or a video or photo icon when there is no picture, plus the name and Video or Photo. A library file keeps the Library label. A local video that is also in playlists stays one result and lists those names. An online video is one result and opens from the first of those playlists. A photo opens in the preview. Coming back keeps that search text, the results, and the scroll position until the app closes. Library, each playlist, and Saved words do the same, and the list beside the player keeps one search per video. Library also keeps the album that was open. `SearchSession` holds that in memory for the session. A recent photo has no play mark. A row is hidden when it is empty. Continue watching is not repeated on Library. The video player is a layer over the frame, not a page inside it. The full player covers that area. Leaving it shrinks the same player to the bottom right, and playback continues from the same moment with the same audio, captions, and playlist choices. The small player has play, pause, volume, Close, and Full player. A click on the picture returns to the full player. Opening a different file or stream stops the previous one. A saved word from the video already open seeks to that time and shows the full player. Close stops playback and removes the small player. That choice is not stored in a backup.

Leaving a page that holds unsaved work is decided before navigation. Recordings, Capture, Merge, the video player, the video editor, and the photo preview expose `PrepareToLeave`. The shell calls it first. If the user must be asked, the page shows its own prompt and navigation waits. A dialog opened from `OnNavigatingFrom` is not used, because that crashes this WinUI desktop app. After the page confirms a leave, it calls `MainWindow.SyncNavigationSelection` so the menu highlight follows the open page. Closing the window runs the same prompt when Merge, the editor, Capture, photo markup, or Recordings still has unsaved work or a save in progress. A video save that is still running blocks the close until it finishes. Downloads keep running when you leave Download. Closing the window pauses the active download and any queued download, writes the queue, and keeps the partial file.

The photo stage and the video stage share a black rounded surface. Photo tools sit under the picture. The video bar is the same control for a library video, the video editor, a recording preview, a download preview, and Merge. In the editor it sits under the picture. The editor shows one tool card at a time. Trim is the only mode that shows the white handles. Cut is the only mode that arms remove-part. The editor timeline can zoom from 1× to 16×. The watching player keeps one LibVLC surface and resizes it between the full player and the small player. The editor, Merge, a download preview, and a recording preview each keep their own surface. `PlaybackFocus` lets only one of them play at a time. Starting one pauses the others without discarding their position. Showing the full player pauses any preview underneath it. The download preview is a solid card with its controls above the picture. While the full player is open, the page underneath is hidden and the player is painted with an opaque color, so that page does not show through the video name. The name stays on one line beside the buttons. The full player and the small player share one volume. A download preview keeps a separate volume in memory for the session. LibVLC is started with DirectSound, so each player’s volume is its own buffer instead of the shared Windows audio session. Close on the small player stops the video that was being watched.

## Library storage

`App` creates the library at `%LocalAppData%\PersonalMediaPlayer\Library`. `FileLibraryStore` owns the folders:

```
Library/
├── Images/                 imported and edited photos
├── Videos/                 imported videos, edited videos, and saved recordings
├── Screenshots/            saved captures
├── Recordings/             in-progress takes under .pending, before they are saved
├── Folders/                one JSON file per album, including Recordings
├── Originals/              backups keyed by the library-relative path
│   └── links/              backups of linked files, keyed by a hash of the full path
├── RecentlyDeleted/        one folder per deleted copy, kept for 7 days
├── links.json              files used from their original folder
└── connected-folders.json  folders watched on this PC
```

An item id for a copied file is the path relative to `Library`, with forward slashes, such as `Images/photo.png`. A linked file's id is its full path. Albums store those ids. They do not own a separate copy of the file. `Folders/Recordings.json` is created for saved recordings; the video file itself is under `Videos`. Screenshots are the exception: those files stay in `Screenshots`.

Import and drop ask for a copy or a link. Download, Merge, the editor, and Recordings still copy. Linking a file that is already under `Images`, `Videos`, or `Screenshots` does not add a second row. Deleting a link removes the `links.json` entry, album membership, and only the backup under `Originals/links`. It does not move or delete the file, and the file does not go to Recently deleted. `RelocateLink` points that entry at a new path of the same type after the file moves. A video stays a video and a photo stays a photo. A different type is refused, and the entry stays as it is. Saved words, bookmarks, the playback position, playlists, favorites, and screenshot text follow that path. A missing link stays listed.

**Connect folder** records a PC folder in `connected-folders.json`. Refresh and startup walk that folder and its subfolders. New photos and videos are linked by their full path, with the time they were found. The same path is listed once. Hidden, system, and reparse-point entries are skipped. A folder inside the library, a folder that contains the library, or a folder that overlaps one already connected is refused. A missing folder stays in the list. Disconnect removes only that watch entry. The scan leaves saved words, bookmarks, and the playback position alone.

Screenshots, Recordings, Unfiled, Photos, Videos, This month, Favorites, Duplicates, and Recently deleted are reserved names. A person cannot create an album with one of those names. Photos, Videos, This month, Favorites, Unfiled, and Duplicates are not JSON files. They are computed when the page loads. Duplicates groups files that share a length and a SHA-256 hash. Ctrl+A selects the current library view, Shift+click selects the range, and the selection bar adds those videos to a playlist or adds and removes favorites in one write to `favorites.json`.

Overwrite of an edited photo or an edited video copies the previous bytes to `Originals/{relative path}` before replacing the file. A linked file uses `Originals/links/{hash}{extension}` instead, because its path is outside `Library`. A backup is restored only for that same path. Overwriting a linked file in place changes the original file. A new name writes beside that file, points the link at the new name, and does not delete the old file. Save as new writes another file under `Videos` and adds it to the same albums as the source, except smart views, Screenshots, and Unfiled.

## Other app data

These files sit next to `Library`, still under `%LocalAppData%\PersonalMediaPlayer\`. Settings can export them to a `.pmpbackup` file: playlists, including watched marks, saved words, bookmarks, playback positions, favorites, `Library/links.json`, theme, online audio and subtitles, screenshot cursor and delay, system audio, and listening volume. Export writes a temporary file and replaces the chosen backup only after the zip is complete. Restore checks the records in each file, asks first, then replaces those files. The previous bytes are kept as `recovery.pmpbackup` in the app folder. If putting those bytes back fails, restore reports that failure. Media files, albums, downloads, screenshot text, the subtitle cache, tools, the play queue, video chapters, the choice to show or hide that list, and `Library/connected-folders.json` are left out. Files already found stay in `links.json`. Restoring a backup leaves the watch list on this PC as it is.

| File | Contents |
| --- | --- |
| `favorites.json` | Paths marked with the heart |
| `playback-bookmarks.json` | Video times and notes |
| `playback-positions.json` | Where a library video or a resolved page was left: time, duration, title, thumbnail, and when it was last watched. A point is kept after 5 seconds and dropped in the last 10 seconds. A YouTube page uses `i.ytimg.com` even when no thumbnail was stored |
| `saved-words.json` | Saved caption words: English, Turkish, sentence, video path or page, whether the page needs a lookup, title, cue time, audio language, caption language |
| `playlists.json` | Named lists. A library video is stored as its path. An online video is stored as its page address and title, and that page is looked up again when it plays. The lookup’s captions are offered then. Audio and quality come from the HLS master when playback starts. Each list can play the next item at the end. The saved order is the playback order. Each video can store when it was added. Sorting or dragging rewrites that order. Search on the Playlists page only filters the rows. A page can also store its picture address after it has been opened. The panel beside the player can reorder the list while a video plays. The last removal, move, or sort can be undone until the message is closed or a later edit replaces it. A watched entry stores `Watched` as true. An entry without that flag is unwatched, including an older path string. Closing the panel leaves a card on the video. Opening a video that is not in that playlist hides the card and the Playlist button together. A queued video keeps them so the playlist can continue afterwards. A play queue is not stored in this file |
| `screenshot-text.json` | OCR text for library search |
| `theme.txt` | Light, dark, or Windows |
| `include-cursor.txt` | Pointer in screenshots |
| `capture-delay.txt` | 0, 3, 5, or 10 seconds |
| `include-system-audio.txt` | Speaker audio on recordings |
| `download-queue.json` | Unfinished downloads: link, quality, progress, and the partial file path. A queued row starts again at launch. Closing the app stores the active row as paused |
| `download-history.json` | Saved downloads: file name, link, quality, date, and location. Removing a row does not delete the file |
| `playback-volume.json` | Listening level and the last audible level for the watching player. The full player and the small player share it. A download preview keeps its own level in memory and does not write this file. Editor, Merge, and a recording preview still read and write this level; each live player still has its own buffer volume |
| `stream-languages.json` | Default audio and subtitles for a resolved page. Audio is `original` or a language code. Subtitles are `off` or a language code. A saved word still restores its own languages |
| `subtitle-cache/` | Extracted captions. A local video uses one `.srt` when no subtitle file sits beside it. A resolved page uses `page-` plus a hash and `.vtt` |
| `tools/` | `yt-dlp.exe`, `ffmpeg.exe`, and `deno.exe` for download, page playback, crop, fade, audio extract, and merge |

Renaming a library file, or locating a moved linked file, updates album membership, favorites, bookmarks, playlists, saved words, the resume position, and the screenshot text key. YouTube requests use IPv4. The first lookup downloads `yt-dlp` if it is missing. Deno is downloaded only when no JavaScript runtime is already available.

## Capture and playback

Screenshots and recordings use Windows Graphics Capture. A selected recording area captures one monitor and keeps only the dragged rectangle. Speaker audio is WASAPI loopback of the default render device. There is no microphone. Gaps where the speakers send nothing are filled with silence so the track stays aligned with the pictures.

Video playback uses LibVLC (`LibVLCSharp.WinUI` and `VideoLAN.LibVLC.Windows`). LibVLC is started with `--no-sub-autodetect-file`, and each media gets `:no-sub-autodetect-file`, so a `.srt` beside the video is not opened as a second caption track. The hover frame on the timeline comes from a separate muted `Windows.Media.Playback.MediaPlayer`, so hovering does not seek the LibVLC player. That player is released before a save so it does not keep the file open. A failed save creates the next player only after a new surface exists.

Captions in the download preview and the saved-video player are drawn by `HoverCaptions`, above the playback bar. `SubtitleCues` reads a sibling `.srt` whose name starts with the video name, or extracts stream `0:s:0` with `ffmpeg` into `subtitle-cache`. **CC** lives in the playback-settings gear. It turns that text on and off and calls `SetSpu(-1)`, so LibVLC does not paint a second copy. Hovering a word calls `TurkishDictionary`. A phrase of two to four words in the current line is checked first, from `Assets/en-tr-phrases.json`. Otherwise the word is looked up in `Assets/en-tr.json`. Both files ship with the app. Contractions keep their apostrophe. An ending such as `-ing` tries the base with a final `e` before the bare stem, and a stem shorter than three letters is ignored. Nothing is sent off the PC.

Clicking a word opens a card with the English text, the Turkish meaning, and the sentence. **Save** writes `saved-words.json`. The row stores the library path, or a page address with a flag for whether that page must be resolved, plus the cue time and the audio and caption languages selected then. Opening the row seeks when the media can seek and restores those languages. `LanguageLabels` turns codes into English names. `bn` is Bangla, `es-US` is Spanish (United States), and a native-script name is replaced the same way. Original and dubbed audio keep that word. Automatic captions use one English name per language. Uploaded tracks come first, then the spoken automatic track, then other automatic languages. A translated caption is fetched inside the same yt-dlp run with `--sleep-subtitles 65`, because YouTube answers HTTP 429 until that session is old enough. A caption already in `subtitle-cache` opens immediately.

Edit and Merge keep that first caption track. `SubtitleEdit` splits cues across the kept spans, divides them by speed when speed changed, and offsets each merged clip after the one before it. Fade, crop, and rotate leave the cue times alone. The cues are muxed back with ffmpeg as `mov_text`. A failure there leaves the saved picture in place.

OCR uses `Windows.Media.Ocr`. The image may be scaled up and given more contrast first. Each installed OCR language is tried, and the result with the most words is kept.

Trim on the player, and a trim or cut in the editor that does not also change speed, volume, or crop, uses `Windows.Media.Editing`. One `MediaClip` is opened and cloned for each kept span. A fragmented MP4, the kind with `mvex` and `moof` boxes, cannot be opened that way, so that path first rewrites it as a normal MP4 at the original speed and volume. Trim, cut, and crop together, with no speed or volume change, go through `MediaTranscoder` with hardware encoding. A crop that transcoder cannot apply is written by `ffmpeg` instead. Speed, volume, and a crop whose picture size is still unknown use the Media Foundation source reader and sink writer: video is decoded to NV12 and encoded as H.264, and audio is resampled as PCM and encoded as AAC. Both streams are read together. The sink writer is created with throttling disabled, so a save is not paced to the length of the video. Hardware transforms are tried first and the software encoder is the fallback. The still-frame button uses a frame-server `MediaPlayer` plus Win2D. Photo pixels use `System.Drawing`.

Editor fades are applied after the other edits, on the finished timeline. A video fade with no audio fade copies the audio. `ffmpeg` is also used for rotation, flip, audio extract, and fades. Extract writes MP3 or WAV and does not open the source as a `MediaClip`.

Merge reads each file with `ffmpeg`, then joins the kept spans in `VideoMerger`. Every clip is trimmed, faded, scaled into one even frame no wider than 1920 pixels, and set to 30 fps. Audio is 48 kHz stereo. A clip with no audio gets silence for the kept length so the next clip stays in time. Hardware H.264 encoders are tried first, then `libx264`. The preview clock is the player time minus that clip’s trim start, added to the kept lengths before it. A seek holds the slider until playback is near that time.

Download shells out to `yt-dlp` over IPv4. `TryNormalize` accepts `youtube.com`, `m.youtube.com`, `music.youtube.com`, and `youtu.be`. A single video uses `--no-playlist`. Lookup reads uploaded tracks from `subtitles`, then automatic captions, one English name per language, including translations. The chosen language is stored on the queue item. A translated track adds `--sleep-subtitles 65` to that download. A video download asks `yt-dlp` for `--write-subs` or `--write-auto-subs`, then `--embed-subs` and `--convert-subs srt`. Audio-only items skip that. A playlist address, or a `list=` link with no video id, is read with `--yes-playlist --flat-playlist --playlist-end 200` and no subtitle request. The list stops at 200 episodes. The user picks episodes and one shared selector: best, 1080, 720, 480, 360, or audio only. Each chosen episode is queued as its own watch URL. A watch link that also carries `list=` stays one video. `DownloadQueueHub` owns the queue for the life of the window and starts it from `App.OnLaunched`. The Download page is the lookup, the list, and the preview. One download runs at a time. Leaving the page releases the preview player and leaves the queue running. Ready rows can be checked and saved together into one library album or one folder on this PC. `DownloadBatchSave` copies those files. A name that is already in the PC folder asks before it is replaced. One failure leaves that row ready and the other chosen files still save. The preview **Save** button still saves one file under a name the user types. A queue item remembers its output path, so pause and a later resume continue the partial file. History thumbnails are YouTube image URLs derived from the saved link. **Open** builds a `MediaItem` for that path and navigates to the video player. It does not launch another app.

Bookmarks are stored as times on the source file. An overwrite remaps them: a mark inside a removed span is dropped, earlier removed time is subtracted, and the remaining time is divided by the speed.

## Streaming

`StreamLink` accepts an absolute `http` or `https` URL. The scheme check finishes on the caller. Header reads, redirects, and a short ranged read run off the UI thread, and only while every hop stays `http` or `https`. The player opens when the final response is `video/*`, an HLS playlist type, or a generic type whose first bytes are a known container. An HTML page shows an error and leaves the current page in place. Library **Open link** uses that check. A missing file ending is allowed.

The extension sends `personalmediaplayer://play/?url=` plus the encoded address. A direct file can include the page as a referrer and the element’s current time. A blob player or a known embed sends the page or the embed address with `resolve=1`. Each primary launch registers the `personalmediaplayer` scheme for the current user, pointed at the running exe. A second process writes one line to the named pipe `PersonalMediaPlayer.StreamHandoff` and exits. The open window brings itself forward. Unsaved work on Merge, the editor, Capture, photo markup, Recordings, or an open trim runs `PrepareToLeave` before the player opens. A download keeps running.

`resolve=1` calls `YoutubeDownloader.ResolvePlaybackAsync` (`--write-auto-subs --dump-single-json`, IPv4, Deno when present) and does not call `DownloadAsync`. A combined picture-and-sound stream is preferred when it is at least as tall as a silent picture. Otherwise LibVLC plays the picture and `Media.AddSlave` attaches the audio. An `m3u8` address is the media. When any non-fragmented video exists, fragmented DASH formats are dropped. A page that only has DASH still uses the picture plus an audio slave. LibVLC 3.0.21 rejects an HLS master with six or more audio renditions in one group, so `HlsMaster` rewrites that master to the selected language, keeps at most five renditions in a group, strips subtitle groups, and LibVLC opens the local copy. The rewritten playlist keeps the original language code and `NAME`. Playback settings offer quality, audio, and captions for that stream. `stream-languages.json` chooses the audio and captions when the extension or a playlist opens that page. A named original audio track wins over the rendition marked default. A language that is not on the video falls back to the original audio or to subtitles off. A saved word’s languages are applied first.

Resume position and bookmarks for a resolved page use the page address. Chapters from that lookup are listed while the page plays when **Chapters** has the list open. They are not saved as bookmarks, and a page with no chapters hides the button. **Save a copy** enqueues that page on the Download queue and starts the download. The stream keeps playing. Opening Download is not required. Replay, and one mid-play failure, look the page up again and seek to the last position only when the new stream can seek. A DRM format, or a yt-dlp error that mentions DRM, shows “This video is protected by a license and stays in the browser.” Other lookup failures show the yt-dlp text. The app does not read browser cookie stores.

A stream hides Edit, trim, restore, the snapshot button, and timeline hover frames. The playlist panel and the Playlist button stay only when that video was opened from a playlist, or when a queued video is keeping that playlist. Opening a video that is not in the playlist hides the list, the card on the video, and the Playlist button together. The Words button stays, and the saved-words list stays closed until it is opened. Seek, the 10-second skips, and section repeat turn on only after LibVLC says the media can seek and a length is known. A direct stream stores a saved word against the media address and does not record resume or bookmarks. `dotnet build` does not build `extension/`.

## Build

The app project targets `net10.0-windows10.0.26100.0`, with a minimum of Windows 10 version 1809 (`10.0.17763.0`). `WindowsPackageType` is `None`, and the Windows App SDK is self-contained, so the output is an unpackaged exe.

```powershell
dotnet build src/PersonalMediaPlayer.App/PersonalMediaPlayer.App.csproj -c Debug -p:Platform=x64
```

`bin` and `obj` are gitignored. Publish profiles under `Properties/PublishProfiles` are also ignored by the app `.gitignore`. The extension stays a loose folder, so this build does not compile it.
